# OpenStory Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a small OpenStory marketing homepage and a three-page Fumadocs getting-started section inside the existing monorepo.

**Architecture:** Add an isolated `apps/www` TanStack Start workspace based on the proven Tiempo/Temporal Calendar scaffold. Keep product copy in local MDX, keep the custom landing surface in focused React components, and deploy under a configurable `/openstory` base path with Cloudflare-compatible output.

**Tech Stack:** React 19, TanStack Start, TanStack Router, Fumadocs, Tailwind CSS 4, Vite 7, Cloudflare Workers

## Global Constraints

- The homepage must explain OpenStory and direct developers to **Get started**.
- The desktop manager is not publicly distributed; every download or install reference must say **Coming soon**.
- Direct project dependencies are `@gobrand/openstory-config` and `@gobrand/openstory-vite`; runtime is transitive.
- Initial docs routes are `/docs`, `/docs/installation`, and `/docs/first-story`.
- Reuse structure from Tiempo and Temporal Calendar without copying their product-specific visual treatment.
- Use OpenStory graphite `#1b1c1d`, raised graphite `#222425`, canvas white `#ffffff`, focus blue `#3b82f6`, cool border `#e3e8ee`, and muted steel `#9aa4ad`.
- No blog, pricing, testimonials, newsletter, account system, analytics, CMS, interactive demo, or desktop publishing work.
- All interactive elements need keyboard focus states and motion must respect `prefers-reduced-motion`.
